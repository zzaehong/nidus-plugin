# dev 팀

## 멤버
| 멤버 | 종류 | 맡는 일 |
|---|---|---|
| research | worker | 필요할 때만. 라이브러리 사용법·버전·API처럼 웹에서 확인할 사실을 정리한다. |
| build | builder | 브리프의 레포·브랜치에서 구현하고 테스트한다. 같은 레포에는 한 번에 하나만 돌린다. |

순서: research(필요하면) → build. 레포가 다른 build 작업끼리는 동시에 돌려도 된다.

## 원칙
- 레포의 `CLAUDE.md`·`README` 규칙을 먼저 따른다.
- 작은 커밋, `nidus/<task-id>` 브랜치. main 병합과 push는 사용자가 정한다.

## 완료 기준 예시 (Completion Contract에 옮겨 쓴다)
- 목표한 동작을 확인하는 테스트가 있고, 그 테스트와 기존 테스트가 통과한다(실제 출력으로 확인).
- 변경이 브리프의 범위 안에 있다(`git diff --stat`).

## 검토 체크리스트
- `git -C <레포> log`·`diff`를 직접 보고, 테스트 명령을 다시 실행해 builder의 결과와 대조한다.
- 범위 밖 파일 변경, 지워진 테스트, 건너뛴 검증이 없는지 본다.

## 결과물
`outputs/dev/<레포>.md`: 레포별 작업 이력과 현재 상태(브랜치·커밋·테스트 결과).
